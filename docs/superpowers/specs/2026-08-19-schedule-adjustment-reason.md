# Spec: 项目排期调整必须填写理由

## 1. 问题背景
在项目进度管理中，项目排期（包含“计划截止日”及“预估交付周期”）的变更属于高敏感操作。为了规范项目排期管理，防止随意无理由延期或缩短排期，需要在一线人员及项目总监调整项目、子分组模块、或者具体任务的排期（截止日期/周期）时，强制要求填写“排期调整理由”。该理由将自动记录到项目操作日志（Activity Log）及证据链评论（Comments）中以供备查。

## 2. 方案概要
在所有涉及排期字段编辑的表单中，添加对原有排期数据的变化检测：
- 如果排期字段（计划截止日 `due_date` / `estimated_duration`）发生了实质性修改，则前端表单动态平铺展示必填的“排期调整理由”输入文本域。
- 在用户提交修改时，将此理由（`changeReason`）连同修改后的属性一并提交给后端 API。
- 后端在持久化这些变更的同时，在活动日志（Activity Log）中记录包含排期调整理由的日志详情，并在该节点/任务下自动生成一条【排期调整】类型系统评论，作为可追溯的证据链。

## 3. 范围边界
排期调整的范围包括以下三种层级的编辑：
1. **项目级（Root Node）**：在 `EditProjectModal` 中，当修改“计划截止日”或“预估交付周期”时。
2. **分组/模块级（Sub Node）**：在 `EditSubNodeForm` 中，当修改“预估完成时间 (计划截止日)”或“预估周期”时。
3. **任务级（Task）**：在 `TaskItem` 的编辑表单中，当修改“计划截止日”或“预估周期”时。

如果仅修改了项目名称、负责人、任务名称、任务状态或交付件要求等非排期字段，则无需强制填写理由。

## 4. 技术选型
- **前端交互**：React 状态对比（Current vs Initial）动态控制“调整理由”的必填输入框展示。
- **数据流与 API**：
  - 更新节点 API (`PUT /api/nodes`) 支持在 body 中接收 `changeReason` 字段。
  - 更新任务 API (`PUT /api/tasks`) 支持在 body 中接收 `changeReason` 字段。
- **持久化与日志存储**：
  - `updateNode` 和 `updateTask` 逻辑在检测到排期变化时，向 `activities` 写入带理由的记录。
  - 向 `comments` 集合插入一条自动生成的【排期调整】类型评论。

## 5. 验证标准
- 没有任何排期修改时，保存按钮不需要调整理由。
- 修改排期周期或截止日后，动态显现“排期调整理由 *”文本框，不填写无法提交（前端 required 校验）。
- 提交排期修改后，自动在操作日志面板（ProjectActivityFeed）看到变更记录及对应的调整理由。
- 自动在评论区（CommentDrawer）中生成带有【排期调整】标签的留档评论。
