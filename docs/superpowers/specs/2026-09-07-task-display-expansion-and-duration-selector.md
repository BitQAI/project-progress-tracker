# 设计规格：任务字符完整显示与周期选择器改造（含存量数据推断转换）

- **日期**：2026-09-07
- **设计者**：BitQAI
- **状态**：Draft -> In Review

---

## 1. 问题背景与业务诉求

在当前 WBS 项目管理系统中，存在两个关键的用户体验与数据规范问题：
1. **任务标题被过早截断省略**：任务项（`TaskItem` 等视图）在任务名称上配置了 `truncate max-w-[120px] xs:max-w-[180px] sm:max-w-xs` 等死板的宽度限制，导致约 20~30 个字符（或移动端 10~15 个字符）后就出现省略号 `...`，无法看全任务关键细节。用户期望“尽可能全部显示，不要30个左右后面的就直接省略了”。
2. **预估周期仍为自由文本输入，缺乏规范与半数支持**：目前任务、模块分组、项目创建与编辑表单中的“预估周期”为自由字符串输入框，用户可能随意输入 `1`、`2-3天`、`36人天`、`3周` 等非结构化格式。用户期望：
   - 改造为“选时间”控件，支持单位：**日（天）、周、月（个月）**；
   - 允许以 **0.5（半数）** 粒度进行选择与输入（如 `0.5天`、`1.5天`、`2.5天`、`1.5周`、`0.5个月` 等）；
   - **存量数据自动推断与转换**：系统自动扫描历史存量数据（如 `"1"` -> `"1天"`，`"3-4天"` -> `"3.5天"`，`"36人天"` -> `"36天"`，`"半天"` -> `"0.5天"` 等），并标准化转换为统一新格式，并同步持久化到数据库。

---

## 2. 方案概要

### 2.1 任务字符显示体验优化
- 在 `TaskItem.tsx` 中移除人工死板限制 `truncate max-w-[120px] xs:max-w-[180px] sm:max-w-xs`，替换为高自适应的自流动文本排版模式：
  - 允许任务名称使用 `break-words leading-snug font-medium` 优雅自适应折行展开；
  - 配备完整的 `title={task.name}` 气泡预览；
  - 确保与左侧勾选框、右侧各状态/交付物徽章保持合理的弹性布局关系。
- 同步检查并优化 `NodeDetailDrawer`（节点详情抽屉中的子任务列表）、`TaskFlowNode`（画布中的任务卡片）与 `GanttLeftTree`（甘特图左侧树）的任务名称显示，避免不合理的单行截断。

### 2.2 预估周期选择器控件 (`DurationPicker`)
打造通用的 `DurationPicker` 周期选择组件：
- **核心数据模型**：
  - 数值：支持 `0.5` 步长的非负数值（如 `0.5`, `1`, `1.5`, `2`, `2.5`, `3`, `3.5` 等）；
  - 单位：`['天', '周', '个月']`（展示文案为“天(日)”、“周”、“月”）；
  - 输出格式：`${数值}${单位}`（如 `2.5天`, `1周`, `1.5周`, `1个月`, `2.5个月` 等；空则为未设置）；
- **交互设计**：
  - 数值微调输入框（步长 0.5，最小值 0.5）；
  - 单位选择下拉框（天 / 周 / 个月）；
  - 快捷预设标签药丸（如 `0.5天`、`1天`、`2天`、`3天`、`1周`、`2周`、`1个月`），点击一键填充；
  - 快捷“清空/未设置”操作；
  - 动态格式预览。
- **集成范围**：
  - `TaskEditForm.tsx`（任务编辑）
  - `NodeActionForms.tsx`（添加任务表单、添加子模块表单、编辑模块表单）
  - `EditProjectModal.tsx`（编辑项目表单）
  - `CreateProjectModal.tsx`（新建项目表单）

### 2.3 存量数据智能推断与自动迁移 (`inferAndNormalizeDuration`)
- 建立统一的推断转换函数：
  - 正则匹配与中英文规则提取；
  - 范围表达智能中值计算：`"3-4天"` / `"3~4天"` -> `(3+4)/2 = 3.5天`；`"2-3天"` -> `2.5天`；
  - 纯数字推断：`"1"` -> `"1天"`，`"2"` -> `"2天"`；
  - 人天与工时换算：`"36人天"` -> `"36天"`；`"4h"` / `"4小时"` / `"半天"` -> `"0.5天"`；
  - 周与月标准化：`"1.5周"` -> `"1.5周"`；`"1月"` / `"1个月"` -> `"1个月"`；
  - 无法识别的保留原内容或置空，不发生数据丢失。
- 迁移执行：
  - 编写并执行迁移脚本，批量处理当前 Supabase 数据库和本地数据中所有任务与节点的历史 `estimated_duration`；
  - 在数据加载入口 (`lib/db.ts` 与 mutations) 引入推断保障，确保后续无论是 AI 解析还是旧数据导入，均自动推断转换规范化。

## 3. 影响范围与风险控制

1. **影响范围**：
   - 前端组件：`TaskItem.tsx`、`NodeDetailDrawer.tsx`、`TaskFlowNode.tsx`、`GanttLeftTree.tsx`、`TaskEditForm.tsx`、`NodeActionForms.tsx`、`EditProjectModal.tsx`、`CreateProjectModal.tsx`；
   - 核心工具类：`lib/duration-utils.ts`（新增）、`lib/project-calc-utils.ts`；
   - 数据库：`tasks` 和 `nodes` 表中的 `estimated_duration` 存量字段规范化。
2. **风险控制**：
   - 存量数据转换前对当前任务和节点进行全量核对，确保推断结果与原意高度一致；
   - UI 展开长字符时必须保证在手机/平板/桌面各视口下徽章与操作按钮不换行重叠或溢出视口。

## 4. 验证标准

1. 创建超长标题任务（如 60 个汉字），检查树状列表、抽屉中能否完整清晰显示，不再在 30 字符处被 `...` 截断。
2. 打开任务编辑或创建表单，使用 `DurationPicker` 选择 `2.5天`、`1.5周`、`0.5个月` 等半数周期，成功保存并展示在任务徽章上。
3. 执行存量数据推断测试脚本，验证诸如 `"1"`、`"3-4天"`、`"36人天"` 等历史存量数据已全部成功推断并转换为符合新规范的字符格式。
